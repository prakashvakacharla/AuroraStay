AuroraStay: browser-based Codespaces deployment

The notebook benchmark and local API checks are complete. This guide completes the remaining account-dependent deployment steps. The deployment package is prepared; a GitHub repository, Codespace and external URL have not been created for you.

Prerequisites you handle

  1. A GitHub personal account with permission to create a private repository and use Codespaces. Check your included Codespaces usage and budget before starting; payment details may be needed if your included usage is exhausted.
  2. The funded OpenAI API key already used for this project, with access to gpt-4o-mini and gpt-4o. Keep it in Codespaces secrets, not a source file.
  3. Download AuroraStay_Codespaces_Deployment.zip from the delivered artifacts. It includes the trusted index, source, Compose configuration, dev container, startup/check scripts, and the staff-review workflow. It contains no API key.
  4. For broader live validation, a hotel policy owner or knowledgeable staff reviewer must review the supplied worksheet. That approval cannot be replaced by an AI score.

You do not need Docker Desktop, GitHub CLI, or a personal access token on your Mac for this browser route. The supplied dev container installs Docker inside Codespaces.

1. Create a private repository

Open GitHub new repository. Name it aurora-stay-qna (or another name you prefer), choose Private, select Add a README, and create it. Use a new repository so these instructions do not overwrite existing work.

2. Add Codespaces secrets

Open your Codespaces settings. Under Codespaces secrets, choose New secret and create:

Name Value
OPENAI_API_KEY Your funded API key
OPENAI_API_BASE https://api.openai.com/v1

For each secret, grant Repository access to the private repository from step 1. These must be Codespaces secrets; GitHub Actions secrets are a different store. Do not paste the API key into this chat, a commit, the README, or a terminal command.

If you add/change secrets after starting a Codespace, stop and restart it so the environment receives them. GitHub secret instructions

3. Create the Codespace

In your repository, choose Code → Codespaces → Create codespace. Use advanced options to select a 4-core / 8 GB machine when available; this is recommended for dependency/image builds. Check which account pays before confirming. Wait for the browser editor to open. GitHub creation instructions

4. Upload and extract the prepared package

Drag AuroraStay_Codespaces_Deployment.zip into the Codespaces Explorer area, or use its Upload action. Open a terminal at the repository root and run:

unzip -n AuroraStay_Codespaces_Deployment.zip

The ZIP stores files at its root. You should see compose.yaml, backend_files/, frontend_files/, scripts/, and the hidden .devcontainer/ directory. Do not upload your full local workspace, .venv, .cache, .openai-test.json, or config.json.

Save the deployment files to the repository:

git add .devcontainer backend_files frontend_files scripts validation compose.yaml DEPLOYMENT_GUIDE.md LIVE_VALIDATION.md .gitignore
git add -f backend_files/faiss_index/index.faiss backend_files/faiss_index/index.pkl
git commit -m "Add AuroraStay deployment and validation workflow"
git push

The prepared ZIP includes approved development references used only for judging. The raw PDF collection, held-out test references, local credentials, staff names, and pending review worksheet are not required for deployment and are not uploaded by these commands. The reference catalog and index include policy information; keep the repository private.

5. Rebuild the development container

Open the Command Palette (Cmd/Ctrl + Shift + P) and run Codespaces: Rebuild Container. This applies .devcontainer/devcontainer.json, including Docker-in-Docker and forwarding for ports 7860 and 8501. Wait until the rebuilt editor is ready. It may download substantial dependencies the first time. If GitHub indicates the current machine is too small, change to the recommended machine type before rebuilding.

6. Build and start the app

In the terminal at the repository root:

bash scripts/start_codespaces.sh

This checks the secret and trusted index, validates Compose, builds both images, waits for backend/frontend health checks, and records HTTP/retrieval checks in outputs/deployment_verification.json. It does not print the API key. The first backend image build downloads and caches the embedding model; runtime uses that cached model in offline mode.

Run the paid end-to-end answer check once:

python3 scripts/verify_deployment.py --include-generation

Success includes checks_passed: true, an actual answer/source payload, and a four-metric composite for an approved reference question. An HTTP 200 alone does not prove every generated answer is correct.

If a check fails, inspect the services:

docker compose ps
docker compose logs --tail=100 backend frontend

Missing secret: grant repository access to the Codespaces secret and stop/restart the Codespace. Credit error: check API billing. Model download/build error: inspect the backend build log and retry after network access is restored. No successful Docker build has been recorded in this local Mac environment; the supplied checks must be run in your Codespace before deployment can be called complete.

7. Verify the forwarded browser URLs

Open the Ports tab. Keep 7860 and 8501 Private for this internal POC. Open port 8501 in your signed-in browser and ask:

Select Answer + Relevant Chunks and confirm that the answer, quality scores, route and sources appear. Open port 7860 and verify its health JSON. Copy both actual forwarded URLs from the Ports panel; do not invent them.

A private forwarded URL requires GitHub authentication. A 401/404 from a separate unauthenticated notebook/client may be a port-authentication issue, not an app failure. Do not make a paid, unauthenticated API public merely to bypass that check. If an assessor explicitly requires public access, agree on an appropriate access method before changing visibility. Then open your Codespaces page, stop the Codespace, and delete it when no longer needed. Stopping the app containers does not stop Codespaces compute, and stopped Codespaces still retain storage.

No rows are marked approved by the automated workflow.

For each row, fill:

Field Required action
review_status approved only after checking the policy; otherwise needs_changes or rejected
reviewer Reviewer name or identifiable staff ID
reviewed_date Date as YYYY-MM-DD
expected_answer Independently verified answer, including necessary conditions and exclusions
relevant_context Verified source passage(s) and document/section; separate multiple passages using <>

Do not approve an unsupported question merely because the answer politely abstains. Verify whether the appropriate outcome is a supported answer, clarification request, or manual escalation. Keep the original question, draft, sources, case ID and index_snapshot_sha256 intact for traceability.
